# Демо Garden на GitHub Pages — дизайн

Дата: 2026-10-13

## Цель

Опубликовать интерактивное демо Garden на GitHub Pages. При открытии сервиса сразу видны демо-данные, экран логина пропущен. Правки (создание, редактирование, удаление) работают и сохраняются в браузере посетителя.

## Решения

- **Интерактивность:** правки сохраняются в браузере (IndexedDB), есть сброс к исходным данным.
- **Подход:** реальный серверный код выполняется в браузере. `node:sqlite` заменяется на `sql.js` (SQLite в WASM), Express заменяется мини-роутером.
- **Загрузка фото:** отключена. Аватары берутся из демо-данных.
- **Основная сборка и сервер не меняются.**

## Архитектура

Новая команда `npm run build:demo` собирает отдельный бандл в `dist-demo/` с переменными `VITE_DEMO=1` и `VITE_BASE`.

- **Вход** `src/demo/boot.js` подключается только в демо-сборке. Порядок: загрузить WASM, поднять БД, зарегистрировать роутеры, подменить `window.fetch`, выполнить автовход, смонтировать React.
- **Подмена `fetch`:** запросы к `/api/*` уходят в браузерный роутер, остальные — в оригинальный `fetch`. Страницы и [src/lib/api.js](../../../src/lib/api.js) не меняются.
- **Серверный код без изменений:** `server/db.js`, `server/routes/*`, `server/domain/*`, `server/application/*`, `server/demo-data.js`.

## Шимы (`src/demo/shims/`)

Подключаются Vite-алиасами только при `VITE_DEMO`.

| Модуль | Замена |
| --- | --- |
| `node:sqlite` | `DatabaseSync` поверх `sql.js`: `prepare().run/get/all`, `exec`, нужные `server/db.js` PRAGMA и транзакции |
| `express` | Мини-роутер: `get/post/put/delete/use`, `req.params/query/body/cookies`, `res.status/json/cookie/clearCookie/sendStatus`, цепочки middleware, `express.json()`, `Router` |
| `fs`, `path`, `os` | Заглушки; `server/storage.js` работает с in-memory хранилищем |
| `crypto` | Web Crypto, при необходимости чистый JS для синхронного scrypt/pbkdf2 |

Полнота шима Express проверяется при реализации по фактическому использованию в `server/`.

## Данные и сброс

- Начальные данные — `demoSeed` из `server/demo-data.js`, загружаются той же логикой, что в `POST /api/auth/demo`.
- После каждой записи состояние БД экспортируется (`db.export()`) в IndexedDB с дебаунсом. При открытии восстанавливается, если есть.
- Шапка показывает плашку «Демо-версия» и кнопку «Сбросить данные»: очищает IndexedDB и перезагружает страницу.
- Экран логина пропускается, демо-пользователь входит автоматически.
- `POST /api/photos` возвращает 403 «Недоступно в демо», кнопки загрузки скрыты.

## Публикация

- `HashRouter` в демо-режиме (Pages не умеет SPA-фолбэк).
- `base` берётся из `VITE_BASE`; в Action это `/<имя репозитория>/`.
- GitHub Action: на push в `main` собирает `build:demo` и деплоит `dist-demo/` через `actions/deploy-pages`.
- WASM `sql.js` (~600 КБ) подгружается лениво до монтирования приложения.

## Тесты и проверка

- `npm test` остаётся зелёным.
- Новый `test/demo-shim.test.js`: шим `DatabaseSync` и мини-роутер дают те же результаты, что `node:sqlite` и Express, на наборе запросов из реального API.
- Смоук: `build:demo`, статический сервер на подпути, обход основных разделов в браузере, проверка сохранения правки после перезагрузки и сброса.

## Риски

- Неполнота шима Express — выявляется на реализации; крупные пробелы (например потоковые ответы) будут вынесены отдельно.
- Лицензия: [LICENSE.md](../../../LICENSE.md) проприетарная, а демо публично раздаёт собранный клиент и серверную логику в бандле. Решение за владельцем.
