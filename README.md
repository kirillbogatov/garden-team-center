# Garden

Garden — локальный командный центр для ежедневной работы руководителя и команды. Он объединяет задачи, проекты, людей, встречи, цели и рабочий контекст в одном веб-интерфейсе и хранит данные локально в SQLite.

> Репозиторий содержит исходный код Garden, но проект распространяется по проприетарной лицензии. Публичная доступность исходников не предоставляет права на использование, копирование, модификацию или распространение. См. [LICENSE.md](LICENSE.md).

## Возможности

Garden помогает держать в одном месте операционную и стратегическую картину команды:

- **Ассистент** — быстрые команды и поиск по рабочему контексту;
- **Задачи** — списки, фильтры, приоритеты, подзадачи, связи и канбан;
- **Проекты** — команда проекта, загрузка, связанные задачи и проблемы;
- **Проблемы и договорённости** — фиксация решений и контроль связанных действий;
- **Люди** — команда, стейкхолдеры, профили и загрузка;
- **Встречи и календарь** — 1:1, PR, командные встречи и связанные материалы;
- **Журнал** — личные рабочие записи, закрепление и упоминания;
- **Цели и процессы** — стратегический контекст и связанные сущности;
- **Идеи и Мастерская** — развитие инициатив и проектов с настройкой видимости;
- **План мероприятий** — квартальный план, участники, связанные встречи и экспорт;
- **Знания и инструменты** — рабочая база знаний и каталог инструментов;
- **Заметки на полях** — контекстные стикеры на detail-страницах;
- **Markdown и @-упоминания** — форматирование свободного текста и связи с людьми/проектами;
- **Роли и права доступа** — сотрудник, тимлид и администратор;
- **История версий и уведомления** для ключевых рабочих сущностей.

## Технологии

- React 19 + React Router;
- Radix UI primitives и shadcn-style компоненты в исходниках;
- Tailwind CSS + semantic CSS tokens;
- Lucide Icons;
- Express;
- встроенный `node:sqlite`;
- Vite.

Garden — единый локальный сервис: Express обслуживает API и production-сборку React, а SQLite хранит данные на компьютере, где запущено приложение.

## Быстрый старт на Windows

### Требования

- Node.js **22.5+** с поддержкой встроенного `node:sqlite`;
- npm;
- интернет при первом запуске для установки зависимостей.

Рекомендуется актуальная LTS-версия Node.js.

### Запуск

1. Скачайте или клонируйте репозиторий.
2. Запустите `Garden.bat`.
3. Garden автоматически:
   - проверит Node.js и SQLite;
   - установит npm-зависимости, если их ещё нет;
   - соберёт интерфейс;
   - запустит сервер;
   - откроет `http://127.0.0.1:4173` в браузере.

Рабочие данные по умолчанию находятся вне папки приложения:

```text
Desktop/GardenData/
├── garden.sqlite
└── uploads/
```

Это позволяет обновлять или заменять код Garden, не перенося базу вместе с приложением.

### Первый вход

Если база новая и в ней ещё нет пользователей, Garden создаст первого администратора. Логин и временный пароль будут напечатаны в окне запуска. После первого входа пароль потребуется сменить.

На экране авторизации также доступен запуск **демо-пространства**. Демо использует отдельный workspace и не смешивается с основными данными.

## Ручной запуск

Установите зависимости:

```bash
npm install
```

Соберите клиент и запустите Garden:

```bash
npm run build
npm start
```

По умолчанию приложение доступно по адресу:

```text
http://127.0.0.1:4173
```

Для разработки удобнее запускать backend и Vite отдельно.

Терминал 1:

```bash
npm start
```

Терминал 2:

```bash
npm run dev
```

Vite проксирует `/api` и `/uploads` на backend.

## Онлайн-демо (GitHub Pages)

Демо запускает тот же серверный код Garden прямо в браузере: `node:sqlite` заменён на `sql.js` (SQLite в WASM), Express — на мини-роутер. Бэкенд не нужен, демо-данные из `server/demo-data.js` видны сразу, правки сохраняются в IndexedDB посетителя, а кнопка «Сбросить» в углу возвращает исходные данные. Загрузка фото в демо отключена.

```bash
npm run build:demo     # сборка в dist-demo/
npm run preview:demo   # локальный просмотр на http://localhost:4174
```

Публикация: в настройках репозитория **Settings → Pages → Source: GitHub Actions**. Workflow [.github/workflows/pages.yml](.github/workflows/pages.yml) собирает и выкладывает демо при каждом push в `main`. Ссылки демо работают через hash (`/#/tasks`), потому что Pages не умеет SPA-фолбэк. Сохранённое у посетителя состояние сбрасывается при каждой новой сборке.

Устройство: [scripts/build-demo-server.mjs](scripts/build-demo-server.mjs) упаковывает `server/index.js` через esbuild, подмены лежат в [src/demo/shims/](src/demo/shims/), [src/demo/api-bridge.js](src/demo/api-bridge.js) направляет `fetch('/api/…')` в этот бэкенд.

## Конфигурация

Garden поддерживает следующие переменные окружения:

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `PORT` | Порт HTTP-сервера | `4173` |
| `HOST` | Интерфейс прослушивания | `0.0.0.0` |
| `GARDEN_DATA_DIR` | Папка с SQLite и uploads | `Desktop/GardenData` |
| `GARDEN_ADMIN_USER` | Логин первого администратора | `admin` |
| `GARDEN_ADMIN_PASSWORD` | Пароль первого администратора | генерируется автоматически |
| `GARDEN_SECURE_COOKIE` | Принудительный secure-флаг cookie | зависит от окружения |

`GARDEN_ADMIN_USER` и `GARDEN_ADMIN_PASSWORD` применяются только при создании самого первого пользователя в пустой базе.

## Данные и резервное копирование

Основные данные хранятся в `garden.sqlite`, пользовательские изображения — в `uploads/`.

Для резервного копирования рекомендуется сохранять **всю папку `GardenData`** при остановленном сервере. SQLite работает в WAL-режиме, поэтому копирование только одного `garden.sqlite` во время активной работы может не включить последние изменения.

Если нужно перенести Garden на другой компьютер:

1. остановите Garden;
2. скопируйте всю папку `GardenData`;
3. поместите её в каталог, заданный `GARDEN_DATA_DIR`, либо на рабочий стол по умолчанию;
4. запустите приложение.

## Идентификаторы сущностей

Часть сущностей использует постоянные человекочитаемые ключи:

| Сущность | Пример |
| --- | --- |
| Проблема | `ISSUE-0001` |
| Процесс | `PROCESS-0001` |
| Договорённость | `AGREE-0001` |
| Идея | `IDEA-0001` |
| Проект Мастерской | `BLUEPRINT-0001` |
| Цель | `GOAL-0001` |
| Запись журнала | `NOTE-0001` |
| Инструмент | `TOOL-0001` |
| Встреча | `MEET-0001` |

Обычные проекты используют короткий `projectKey` длиной до четырёх латинских букв/цифр, например `KODE`. Этот ключ используется как префикс проектных задач.

## Архитектура в двух словах

Garden — modular monolith с одним процессом приложения:

```text
Browser
  │
  ▼
React / Vite build
  │
  ▼
Express API
  │
  ▼
SQLite + local uploads
```

Рабочие сущности хранятся в SQLite как JSON-документы. Это позволяет развивать модель данных без отдельной таблицы для каждого продуктового объекта, сохраняя транзакционность SQLite и централизованные правила доступа.

Основной и демо-workspace логически разделены внутри одной базы.

## Безопасность и доступ

- рабочие API требуют авторизованную сессию;
- пароли хранятся как хэши с индивидуальной солью;
- после серии неудачных входов применяется временная блокировка;
- роли и доступ к разделам проверяются на сервере;
- пользовательские uploads доступны только после аутентификации;
- приватные элементы Мастерской используют явную видимость `Команда / Только я`.

Garden рассчитан прежде всего на локальное или доверенное сетевое окружение. Перед публикацией экземпляра напрямую в интернет необходимо самостоятельно обеспечить HTTPS, reverse proxy, сетевые ограничения, резервное копирование и эксплуатационный мониторинг.
